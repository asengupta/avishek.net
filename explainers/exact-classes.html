Exact field classes across programs

TL;DRTwo fields in different programs hold the same datum when every byte of one lands, in place, on every byte of the other. Follow bytes, not names, and let table occurrences and file slots pass bytes through without counting as fields themselves.

Read first: From byte provenance to a field graph

A caller and a callee often declare one datum under two names, and only the bytes say so. This page finds such pairs from the field graph's byte placements alone, and joins them into classes.

The test

Field A (program P) and field B (program Q, not P) are one class when:

  1. they are the same size;
  2. byte i of A lands on byte i of B, for every i;
  3. no byte of A lands anywhere else in B.

Classes are the connected components of the pairs that pass. Copies inside one program never join: a program copying a field to a work area is not evidence of a shared datum.

The example

Program R hands a commarea to program S. S receives it into a linkage table of 1-byte occurrences T(1) to T(4) and moves bytes out into its own fields.

Relays

The table occurrences T(1) to T(4) are not fields anyone would call a datum. They are just how S declared the bytes it received. So they relay: a byte that lands on a relay keeps going to wherever the relay sends it, and only the far end counts.

  • Relays are subscripted fields and dataset slots.
  • Following a byte through relays is reachability in a graph of byte-to-byte moves.

Each pair, judged

pairbytes landverdict
R:CA.A, S:WS.B0→0, 1→1, via T(1), T(2)joined
R:CA.C, S:WS.D0→1, 1→0no: out of place
R:CA.E, S:WS.F0→0, 1→1, but sizes 4 and 2no: sizes differ
S:WS.B, S:WS.Gin placeno: same program
R:CA.H, S:WS.Jin placeno: J is reached by an edge with no placement

The result is one class: {R:CA.A, S:WS.B}.

The last row is the strict rule. K → J has no known placement, so nobody can say which of J's bytes it overwrote. A field reached by such an edge neither relays nor joins.

Through a file

Dataset slots relay the same way, over exact dataset edges. W writes an 11-byte ID; R reads it back as one 11-byte field; the record is cut into slots [0:5] and [5:11]:

edgealignment
W:R.ID → DS[0:5]bytes 0–4 to 0–4
W:R.ID → DS[5:11]bytes 5–10 to 0–5
DS[0:5] → R:R.ID0–4 to 0–4
DS[5:11] → R:R.ID0–5 to 5–10
DS[0:5] → R:R.GRP0–4 to 0–4
DS[0:5] → Q:R.IDpossible, no placement
W:R.ID → Q:R.ID0–10 to 0–10

The class is {Q:R.ID, R:R.ID, W:R.ID}. R:R.GRP is five bytes, so it does not join an 11-byte field. The possible edge into Q is ignored, and does not stop Q joining through its direct edge.

The rule

moves(byte) = bytes an aligned edge carries it to
onward(b) = {b} if b is not on a relay; else b and everything reachable from it
landings(a, i) = { onward(m) | m ∈ moves((a, i)) } restricted to non-relay fields
unplaced = targets of a field-to-field edge with no placement
exact(a, b) = program(a) ≠ program(b) ∧ size(a) = size(b)
    ∧ ∀ i: { offsets of b in landings(a, i) } = { i }
classes = connected components of exact pairs, unplaced fields left out

Loosening it

Each condition costs recall. Measured on CardDemo, loosening one at a time (baseline: 90 classes, 394 fields):

loosenedclassesfieldsprecision, by sample
ignore the unplaced rule92448held: commarea copies joining classes they belong to
allow joins in one program4341,727mixed: one value fanned out to 42 fields becomes one class
accept 75% of bytes in place90394no effect
a field inside a bigger one45438collapses: chains merge distinct fields

Only the first is offered, as --join-unplaced.

On CardDemo

Through a file. The card number in the cross-reference record is one class of eight fields, one per program, though no program writes the file:

CBACT03CCBACT04CCBTRN02CCBTRN03CCOACTUPCCOACTVWCCOBIL00CCOTRN02C

All eight are CARD-XREF-RECORD.XREF-CARD-NUM, 16 bytes, meeting in the record's slot [0:16]. Two readers of the same bytes stay out:

  • CBSTM03B reads the record into a 1,000-byte field. Its bytes 0–15 do land on slot [0:16], but a 1,000-byte field is not the same size as a 16-byte one.
  • CBTRN01C's read never resolved to the dataset (no JCL step runs it), so it has a slot of its own.

Through a commarea, and the strict rule. CDEMO-USER-ID in the shared commarea copybook joins three programs under the strict rule, and six with --join-unplaced:

runCDEMO-USER-ID's class
strictCOCRDLIC, COCRDSLC, COCRDUPC
--join-unplacedCOACTUPC, COACTVWC, COCRDLIC, COCRDSLC, COCRDUPC, COMEN01C

The flag changes only one thing, the unplaced rule, so in the other three programs the commarea field is also reached by a move with no known placement, and the strict rule leaves it out. CDEMO-ACCT-ID forms no class at all under the strict rule, and a six-program one with the flag.

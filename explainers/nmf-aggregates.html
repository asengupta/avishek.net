Domain aggregates by matrix factorisation

TL;DRWrite down which fields each paragraph touches as a 0/1 matrix. Fields that belong to one concept get touched together. Non-negative matrix factorisation splits the matrix into a few groups of fields, each with the paragraphs that use it.

Read first: Exact field classes across programs

An aggregate is a set of fields that make up one concept and are read and written together. A customer's name and address; an account's balance and limits. This page shows the encoding, why NMF suits it, and how rounds handle fields of very different popularity.

The encoding

  • Rows are paragraphs, (program, paragraph). A paragraph is a unit of behaviour: it does one job, so the fields it touches belong to the job.
  • Columns are fields, named PROGRAM:RECORD.FIELD. Every member of an exact class is replaced by the class, so one datum is one column across programs. Table occurrences fold into their declared field.
  • A 1 where any read in the paragraph covers the field, or where the paragraph wrote what such a read sees.

Nothing is counted in pairs or weighted. An earlier version scored field pairs by pointwise mutual information. It dropped every field seen in fewer than three paragraphs, so rare fields had empty rows.

NMF

Non-negative matrix factorisation approximates the paragraph × field matrix X as a product of two smaller non-negative matrices:

X ≈ W H    W ≥ 0 (paragraphs × k),  H ≥ 0 (k × fields)
minimise ‖X − W H‖²
  • Row f of H is factor f's field loadings: what the aggregate is made of.
  • Column f of W is its paragraph loadings: where it is used.
  • k is the number of factors, chosen per round.

Why it should work

Model each paragraph as touching the union of a few aggregates: an update paragraph touches the record it updates and a status field. Then each row of X is roughly a sum of a few aggregate rows, which is exactly what W H can express.

Non-negativity is what makes the factors readable. Nothing can be subtracted, so a factor can't be "these fields minus those". Each factor has to be a part that adds up with others. Lee and Seung's 1999 paper showed the same effect on faces: NMF learned parts such as noses and mouths, where principal components learned whole-face templates.

That holds only if paragraphs really do work on a few aggregates each. A paragraph that touches a hundred unrelated fields, such as a commarea copied whole, is a row no small k explains well. Hence the field exclusions, and the diagnostics.

The example

Fourteen paragraphs and fourteen fields in three planted blocks. Every cell inside a block is 1:

With k = 2 over the fields seen in at least 4 paragraphs, NMF returns blocks 0 and 1 as its two factors: each factor's top fields are one block's fields, and its top paragraphs are that block's paragraphs.

Rounds

Popular fields dominate a single fit, so decompose works in rounds of decreasing threshold. Each round:

  1. keeps the columns of fields seen in at least its threshold of paragraphs;
  2. subtracts what earlier rounds' factors rebuild there, clipping at zero;
  3. factors what is left.

Round 2 sees all fourteen columns, but round 1's factors already rebuild blocks 0 and 1, so almost nothing is left of them. Its single factor goes to block 2.

Keeping it sparse

The residual looks dense: max(0, X − rebuilt), where rebuilt is a full matrix. On a production corpus that is 65,327 paragraphs × 592,104 fields, about 300 GB as doubles. The first version built it, and died before the first fit.

But factors are never negative, so rebuilt is never negative. Where X is 0, the residual is max(0, 0 − something ≥ 0) = 0. So the residual is non-zero only where X already is:

residual(i, j) = max(0, X(i, j) − Σrounds W(i, ·) · H(·, j))   only at X's non-zeros
cost per round = non-zeros × k

The answer is the same up to floating-point rounding, at a fraction of the memory. A synthetic matrix of 100,000 paragraphs, 600,000 fields and 4.5 million non-zeros ran three rounds in 50 seconds and 1.2 GB.

What goes wrong

  • A small k over many programs. If most columns belong to one program each, the matrix is nearly one block per program. With thousands of programs and k = 16, each factor goes to the biggest remaining block, one program's most-touched fields, and structure inside a program never surfaces.
  • Hub fields. Fields that almost every paragraph of a program touches, such as commarea fields, fill a factor's top fields. Exclude them by pattern, or they are the aggregate every time.
  • The threshold. A field below every round's threshold is never factored.
